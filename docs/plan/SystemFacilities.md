# 系统基础能力设计与交付范围

本轮实现环境读取、文件系统、单调计时与 UTC、二进制/标准流 I/O、同步程序执行。
协程、共享内存线程、异步任务、持续交互终端不在本轮范围。

## 已实现的模块边界

| 包 | 职责 |
| --- | --- |
| os | 环境读取与有界的同步程序执行 |
| path | 不访问文件系统的 POSIX 路径文本处理 |
| fs | 元数据、目录、文件操作与临时资源 |
| io | 文件内容与标准流读写 |
| time | 时间表示、转换与单调测量 |
| bytes | 固定长度可变字节存储 |

公共接口、默认值和边界以 docs/Stdlib_zh.md、docs/Stdlib_en.md 及各包 README 为准。
新模块追加注册，既有根绑定位置保持不变，不新增核心值标签或包专用 VM 指令。

## 错误和资源合同

- 纯环境读取是严格接口；getenv 返回 found/value，未设置不等于空值。
- fs、文件 io 提供严格版本和 try_ 版本；后者使用已有 ok/value/code/error/errno 模型。
- os::run 对错误调用参数报错，对启动、捕获、超时、信号终止返回执行记录。
- 子程序非零退出码是被测程序的结果，不能自动当作语言运行错误。
- 输出按字节保存，不隐式解码或删除换行；捕获限制后继续排空。
- 直接子进程始终回收；取消和超时处理进程组，清理有界管道等待。
- 程序执行不通过 shell，显式调用 shell 时由使用者选择解释器与命令文本。
- 不修改进程全局 cwd、环境或信号处理器。信号掩码只作用于等待线程，原掩码在返回前恢复。
- 进程组和路径规范化都不是安全沙箱；跨平台保证当前限于 Linux/macOS。

## 验收

- 环境空值/缺失、时间范围、日历校验、UTC 与本地时区分离。
- 目录排序、父目录创建、悬空链接、拒绝覆盖、非递归删除和临时资源清理。
- 0..255 全字节读写、NUL、无效类型不先截断文件。
- 程序参数不经过 shell；cwd/env/PATH 仅影响子进程；退出 127 区分启动失败。
- 大量双向数据、双路输出、输出截断、EPIPE、超时升级终止、后代管道及信号取消。
- 文件描述符清理、信号掩码恢复、源码/字节码执行、编辑器及安装后验证。

## 代码组织与维护约定

- os/run.c 入口按校验、准备、启动、等待、清理、构造结果排列；等待中的输入写入、输出捕获、取消和终止升级各自使用独立辅助函数。
- 每次运行的资源与状态集中在 run_state；管道角色、执行状态和选项标记均使用具名枚举，默认值与清理期限使用具名常量。
- 运行中的第一个失败决定返回状态，后续清理错误不得覆盖原因。所有描述符在初始化时设为 -1，关闭后立即复位；只有持有资源的一方负责释放。
- fork 后的子进程路径只使用异步信号安全操作，不调用对象分配、通用运行时错误或 stdio。
- fs 分离参数校验、默认结果、实际操作和严格/可恢复结果交付；不依赖枚举值排列判断操作是否修改文件。
- io/fs 使用 system.h 的公共路径校验与错误映射，避免同一系统错误在不同包中产生不一致代码。
- 原生函数的导出描述保持显式，便于核对签名、补全信息和参数边界；不添加只为缩短代码的宏层。

## 下一阶段：测试错误隔离（设计项，未实现）

不直接把任意函数放在 longjmp 周围当成通用 try_call。现有原生函数并非全部能在异常跳出时
释放临时资源，函数闭包和库环境也可能在失败前发生修改。

建议测试运行器以模块入口和显式数据为边界，在独立执行环境运行案例，返回成功、规则违反、
执行失败或预算耗尽；先验证错误后的清理与下一案例可执行，再允许共享更多运行状态。
实现前需增加通用的异常清理登记机制、隔离错误上下文及中断预算，审计原生回调的资源所有权。
这些都是运行时合同，不通过 os 包隐藏实现。

## 下一阶段：状态快照（设计项，未实现）

先定义支持的值域，不把浅 copy 改成深 copy。快照应保存图中对象身份和引用关系，能够区分
共享子对象与两个独立对象；循环结构必须明确支持或在写入前拒绝，不能递归到栈溢出。

建议从标量、String、Time、List、Pair、Dictionary、数值/布尔数组和 Buffer 开始，
以不可变的包对象保存快照；恢复产生独立的可变对象图。Function、Library、Rule 的捕获环境
及未知原生对象先明确拒绝，后续通过可审计的扩展协议支持。稳定比较与持久化格式另行版本化。
