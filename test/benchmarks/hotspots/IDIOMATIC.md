# 现有语法与标准库下的惯用写法优化

后续已增加原生 List 字典序并更新 Dijkstra 的默认堆写法，见 [字典序优化](LIST_ORDER.md)。本文保留该轮实验快照，当前性能以上一级 README 为准。

后续 Lua 全量写法复核发现并保留了 11 项额外改进，见 [Lua 写法审查](LUA_AUDIT.md)。本文描述的是当时的候选范围，不能作为 Lua 已无写法优化空间的证据。

复核固定 16 项综合算法，保留七项 Tapas 算法的写法改进，并同步更新对应的 DP 行和构树热点。Python、Lua 的参考实现也独立筛选；最终保留 23 份源码改动。算法、输入、重复次数和计时边界保持原合同；本轮使用同一个普通 Release 运行时，没有增加语法或标准库 API。

候选先逐项对照，再对保留组合做三轮、每轮七对的交替源码 A/B；每轮各丢弃一次预热，轮间反转先后顺序。每次结果必须一致。测量期间没有并行构建或正确性测试。表中 B/A 是同一 Tapas 二进制执行变体/原版的配对比值，不是 Tapas/Python，也不是性能占比。

|---|---:|---:|---:|---|---|
| `huffman` | 2.120 | 0.076 | 0.035 | 0.034–0.037 | 0.035 / 0.036 / 0.034 |
| `longest_common_subsequence` | 14.887 | 13.501 | 0.908 | 0.895–0.923 | 0.915 / 0.896 / 0.908 |
| `sudoku` | 364.868 | 259.397 | 0.713 | 0.707–0.722 | 0.711 / 0.716 / 0.713 |
| `k_nucleotide` | 110.423 | 92.068 | 0.837 | 0.828–0.843 | 0.835 / 0.827 / 0.843 |
| `merge_sort` | 4.870 | 4.140 | 0.862 | 0.832–0.885 | 0.878 / 0.847 / 0.876 |
| `kmp` | 20.904 | 17.595 | 0.838 | 0.829–0.846 | 0.845 / 0.837 / 0.833 |
| `binary_trees` | 730.136 | 541.571 | 0.742 | 0.739–0.745 | 0.742 / 0.739 / 0.743 |

IQR 是配对比值中间一半的范围，不是置信区间。独立中位数之比不一定等于配对比值中位数。

- Huffman：对本来就固定的小字母表调用通用 count，直接构造正频数节点，省去频数字典。合并、建树和树遍历仍完整执行。逐符号计数为 O(k*n)，适用于这个小且已知的字母表，不能外推为任意规模频数表的最佳算法。
- LCS：仍分配、交换两行，逐列写入 current；用 preceding 和 diagonal 保存左侧、左上单元，减少重复 List 读取。
- Sudoku：递归携带下一个搜索起点，跳过已知填满的前缀，保持首个空格及数字 1–9 的 DFS 顺序；候选检查使用范围循环。
- k_nucleotide：k=1 直接迭代字符，k>1 保留全部重叠切片和完整计数；不依赖计时输入的周期或已知总量。
- merge_sort：缓存左右长度，归并结果使用可返回的 var 绑定；不再浅复制刚构造的结果。长度 ≤1 时返回输入，算法不修改输入。
- KMP：缓存模式长度，前缀表和完整文本扫描不变，每轮仍重新建表。
- binary_trees：false 是不可变叶标记，内部节点直接由两个递归结果构造，仍逐个新建 List。所有叶子的递归调用和完整树遍历保留，没有共享任何内部子树。

## Python、Lua 参考同步复核

Python Huffman 改用 str.count，省去 Counter；保留八符号负载上合适的线性最小值选择。Tapas 与 Python 的频数扫描都在计时内，每次重新读取文本，没有复用上次计数。Lua 的 gsub、逐符号 gmatch、逐字符 gmatch 和字节键方案均未给出更好的稳定结果，保留一趟显式统计。

三语言 LCS 都缓存左侧/左上单元、仍保留两行。三语言 Sudoku 都使用下一个扫描起点，三语言归并都缓存长度、允许直接返回无需排序的小输入。Python/Lua 的默认树都改用不可变 false 叶标记；每个内部节点仍分别新建 tuple/table。Lua 的 k=1 也直接迭代字符。

| 改动 | Python 配对 B/A | Lua 配对 B/A |
|---|---:|---:|
| Huffman 原生计数 | 0.066 | 保留原版 |
| LCS 行内缓存 | 0.900 | 0.929 |
| Sudoku 跳过已填前缀 | 0.910 | 0.829 |
| binary_trees 叶标记 | 0.961 | 0.766 |
| merge_sort 长度缓存及直接返回 | 0.833 | 0.841 |
| k_nucleotide 单字符迭代 | 已有该写法 | 0.964 |

热点 tree_build 随算法调整内部构造与叶标记：Tapas/Lua 的 B/A 为 0.749/0.731，Python 约 1.000。Python 的 --matched 仍用新 List 节点和新 List 叶子作为对象表示控制，不把它替换成默认参考。dp_row 三语言都缓存左侧和左上值，B/A 分别为 Tapas 0.959、Python 0.949、Lua 0.948；Python 的索引控制同步修改，输出完整 DP 行的合同不变。

## 未保留候选与原因

**sieve 的范围循环没有确认稳定收益。** 初筛及首轮复测曾给出正向中位数，但最终主表一次测量中也有小幅变慢。继续以三轮各 21 对的[独立复测](experiments/idiomatic_sieve_repeat.json)检查，B/A 为 0.989，三轮 1.011 / 0.964 / 0.988，IQR 为 0.943–1.043。不能从这些结果断言它稳定更快或更慢。源码确认范围循环减少重复乘法，却增加平方根调用，并使函数需要 for 的循环状态保存/恢复；原 while 仅用分支，不需要该状态。这是实际的执行路径取舍，尚未逐项量化周期。当前原整数 while 更直接，保留已有 fill/count，不为尚未确认的微小收益增加这项改动。[含该候选的中间主表数据](experiments/idiomatic_for_bound_comparison_results.json)留档，不与最终源码混用。

**字符迭代并非当前 Tapas LCS 的更好写法。** 直接遍历两侧字符串为 1.119，加入行内缓存后仍为 1.062。直接参与比较的两个字符串索引可以保持内部单字节立即值；迭代出的 String 与局部字符会进入不同的对象/比较路径。最后保留行内缓存及原来的索引比较。对应快路径见 [REMAINING_GAPS.md](REMAINING_GAPS.md)。

**提升变量要区分存储类别。** 皇后案例把循环内 let 搬成函数级 var 后为 1.056，改为函数级 let 后约 1.001。var 使用环境槽，let 使用临时槽；前者没有减少冲突检查，却改变了热循环的变量访问和生命周期。原版循环局部 let 更清楚，保留。

**省复制也可能增加更热的访问成本。** k-mer 把 counts 改为 var 直接返回为 1.026；临时 counts 加末尾可返回绑定为 1.002，未形成收益。这里只复制很小的键表，热循环却访问 counts 数十万次；原版 let+copy 的单一结果接口继续保留。Dijkstra 改返回存储类别或末尾绑定约 0.999/1.004；其复制量小于搜索和比较工作，没有足够证据引入额外绑定。line_search 的返回候选约 0.987–0.999，变化较小，保留现有更直接的写法。

**Pair 更小不等于构树更快。** 共用 String 叶的 List 树约 0.962，Pair 树约 1.009；List 有 VM 直接索引路径，Pair 还走通用能力读取，缩小节点没有消除递归及引用成本。改用立即值 false 和内联 List 构造取得更好结果。改成 node==false 又省掉每个节点的一次根函数调用，比 identical 检查更合适；仅在这个 List/Bool 表示合同下使用它。

**整数叶标记也没有更快。** 进一步将 false 换成 0，构树热点三轮各十一对的[复测](experiments/idiomatic_tree_marker_ab.json)为 1.038，三轮 1.030 / 1.043 / 1.038，IQR 1.018–1.046。整数比较可以融合分支，但 PUSHI 还会尝试其他融合路径，返回整数叶时也会经过这些检查；内部 List 与整数的比较又不能命中数值融合。PUSHB 的生产路径更直接。源码确认了这些执行差异，但未单独量化每项周期，不能只看到整数 EQ 快路径就推断整个构树任务更快。最终保持 Bool 叶标记。

**小容器不一定适合批量搬移或原生堆包装。** 归并的 concat 尾部方案约 0.907，劣于单纯缓存长度约 0.879；它在许多短合并中新增切片和结果容器。Python Huffman 的串号堆控制约 1.017，轮间方向混合；八节点下包装、串号和分配并未形成稳定收益，继续保留简单线性选择。

Lua gsub 频数候选约 1.221：它对八个符号重复模式扫描，还构造替换字符串。字节键初版包含重复方法查询，缓存 string.byte 后回退从约 1.146 缩至 1.064，轮间仍有混合；它仍有逐字符调用和更新，没有消除频数循环。对小型已缓存字符串键，不能只按“整数键应该更快”判断。保留清楚的一趟统计，不把小幅不确定变化解释为已定位的底层缺陷。

Dijkstra 的直接迭代 Tapas 初筛 0.990、复测 1.008，Python 复测约 1.001。两种写法的图搜索与堆比较工作相同，仅替换少量外层/归约操作；泛型迭代与范围+索引的执行路径不同，现有数据不足以分清真实小差异与测量波动，因此不作为性能改进保留。matrix_multiply 的转置约 0.992，也没有稳定收益；这增加分配和预处理，却没有减少乘加或 VM 索引次数，保持原版。

其他综合案例延续已有的候选选择，不为了让每个文件都有改动而改变算法或浮点顺序。

## 正确性与最新报告

固定 44 项三语言校验和不变。小输入验证继续覆盖 14 组内核，并加强以下内容：筛法跨越平方数边界；归并的空/单元素/重复元素结果及输入不变；七种 Huffman 输入以独立最小权重合并计算总代价；Sudoku 检查完整解、已完成棋盘、无解棋盘及失败后的棋盘恢复。

DP 行、直方图及堆输出的 64 次完整结果检查通过。七项变更算法及筛法对照在 ASAN 下全部执行并核对输出；报告脚本 12 项测试通过。diagnose_script.py 的 ablation 已对应新源码更新，十二份当前对照程序全部通过校验，避免旧替换模式失效。
