# N-body 剩余差距诊断

当前主表为 Tapas 23.965 ms、Python 3.14 20.214 ms，耗时比 1.186。最近一轮运行时 A/B 为 0.994，说明字符比较、动态局部初始化优化没有显著改善本例。下述诊断未修改正式 benchmark，也未重新生成主表。

## 实际执行路径

Python 预热后的 `advance` 包含 `LOAD_ATTR_SLOT`、`STORE_ATTR_SLOT`、Float 专用加减乘、`BINARY_OP_SUBSCR_LIST_INT`、`FOR_ITER_RANGE` 和 `CALL_BUILTIN_O`。`__slots__` 提供固定偏移的对象引用槽位，并不是原生 double 数组。

Tapas 的 Body 类型约束字段，但实例仍使用 Dictionary。字段访问已有常量键与槽位缓存，命中后校验表槽和键，不能误说每次都重新计算字符串哈希。当前字段融合覆盖“两次字段读取、一次算术、立即写回”，而本例主要为：

```tapas
let dx = bi::x - bj::x
bi['vx'] = bi::vx - dx * mj
```

第一种把结果存入局部变量，第二种包含局部变量乘法，都不符合上述完整字段写回融合。简单 `record_update` 已比 Python 快，不能用它替代本例复杂更新的测量。

5 个物体、5,000 步产生 50,000 次两体相互作用；按源码计，advance 约有 850,000 次字段读取、375,000 次字段写入、400,000 个内层局部绑定，以及 50,000 次 sqrt 调用。统计不含初始化和最终能量计算。字段、临时值和分派的微小成本因而会反复累积。这是路径分析，不是各部分耗时占比的测量。

## sqrt 单因素实验

实际 Tapas 字节码中，`math::sqrt(d2)` 经过包字段读取和通用 `OP_EVAL`。仅在 advance、energy 函数入口各缓存 `let sqrt = math::sqrt`，循环内调用 `sqrt(d2)`；公式、算法、浮点运算顺序及输入不变。

同一最终 Release 二进制，5 轮 × 11 次，交替 A/B、隔离自动字节码缓存，各轮预热一次：

| 项目 | 结果 |
| --- | ---: |
| 原写法中位数 | 24.769 ms |
| 缓存 sqrt 中位数 | 23.648 ms |
| 配对 B/A | 0.955 |
| 配对四分位区间 | 0.946–0.968 |
| 五轮中位比值 | 0.954 / 0.955 / 0.960 / 0.950 / 0.958 |
| 两侧校验和 | 199830979999 |

缓存函数耗时约降低 4.5%，证明包成员读取与调用路径有实际优化空间，但不能用它解释全部 18.6% 差距，也不能将其与另一批次 Python 耗时直接相除。
