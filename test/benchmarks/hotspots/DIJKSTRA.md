# Dijkstra：比较次数与回调边界

后续已增加原生 List 字典序并更新 Dijkstra 的默认堆写法，见 [字典序优化](LIST_ORDER.md)。本文保留该轮实验快照，当前性能以上一级 README 为准。

以下为通用堆优化前的诊断快照；后续实现与 A/B 结果见 [通用堆优化](HEAP_OPTIMIZATION.md)，最新跨语言数字以上一级 README 为准。

诊断时普通 Release 主表为 Tapas 8.434 ms、CPython 3.14.2 3.349 ms，约 2.52 倍。
两侧均使用二叉最小堆与过期记录跳过策略；原始数据与探针见
[dijkstra_diagnosis.json](experiments/dijkstra_diagnosis.json)。本文的工作量计数来自独立插桩运行，不使用插桩耗时作为性能结果。

## 实际工作量

一次完整 benchmark 执行四轮、每轮四个起点，共 16 次 Dijkstra。

| 实现与顺序 | 入堆（不含初始记录） | 出堆 | 顶点展开 | 边扫描 | 比较调用 |
|---|---:|---:|---:|---:|---:|
| Tapas 当前：只比较距离 | 7,420 | 7,436 | 4,000 | 28,000 | 100,624 |
| Python 当前：距离、顶点字典序 | 7,436 | 7,452 | 4,000 | 28,000 | 70,232 |
| Tapas：距离、顶点字典序 | 7,436 | 7,452 | 4,000 | 28,000 | 103,388 |
| Python：只比较距离 | 7,412 | 7,428 | 4,000 | 28,000 | 68,292 |

当前并列顺序略有差别，但顶点展开和边扫描相同，入堆差异约 0.2%。
统一为字典序后，入堆、出堆和扫描工作完全一致，Tapas 比较次数仍多约 47.2%。
Python 的比较次数通过覆写 tuple 子类的 __lt__、保持同样排序关系计数；正式 Python 案例继续使用普通 tuple 与 _heapq。

Tapas 的 sift_down 每层先选较小子节点，再比较父节点以决定是否提前结束。
Python heapq 采用将较小子节点逐层提升到底部、再将末尾元素向上调整的策略，减少 pop 中通常不会提前结束的父子比较。
本机 Python 3.14 的 heapq.py 包含这一策略及其动机，实际 _heapq 的比较次数也由上述探针核对。

## 比较本身的成本

Tapas 原生堆每次调用 distance_less 都经过 VM 服务进入 Tapas 函数，读取两个 List 的第零项、
执行比较并返回 Bool；堆随后校验返回类型和容器状态。Python 案例使用 _heapq 和 tuple 的内建比较，不执行用户定义的 Python 比较函数。

为单独检查这一边界，使用相同的 1,000 个整数、20 轮相同入堆/出堆，
只将默认数值比较替换为 `(a, b) { return a < b }`。三轮各七对有效样本，预热一次并交替执行：
默认比较 3.624 ms，Tapas 回调 16.503 ms；配对 B/A 为 4.567，三轮为 4.609、4.495、4.597。
这是完全相同数值堆操作的回调对照，说明原生堆中的逐次 VM 回调成本显著；
它不是 Dijkstra 的精确开销占比，不能与比较次数比例直接相乘解释整段算法。

## 其他单因素对照

均使用同一普通 Release 二进制，三轮各七对样本，源程序和逐次数据保存在上述 JSON。

| 变化 | 配对 B/A | 三轮 | 解释 |
|---|---:|---|---|
| 按距离、顶点字典序比较 | 1.268 | 1.271 / 1.267 / 1.264 | 额外字段读取和比较带来稳定成本；统一并列顺序没有消除差距 |
| List 记录改为 Pair | 1.266 | 1.271 / 1.268 / 1.228 | 该运行时上不是有效替代，不能仅凭对象更小推断更快 |
| 图成员判断+读取改为 idx_or，复用空邻接表默认值 | 0.989 | 1.003 / 1.017 / 0.981 | 四分位区间 0.965–1.033，不能确认稳定收益 |

Pair 记录仍经过同一 Tapas 比较回调，但改变了分配和索引路径；该实验未单独区分这两部分，
不能宣称已精确解释其退化。图查询对照同样不支持把重复查表视为主要瓶颈。
复制返回结果、校验和循环等仍有语言写法差异，目前未单独量化其占比。

优先方向是改进通用堆的下沉策略，减少所有比较；其次是设计能减少逐次 VM 比较回调的通用机制。
这些诊断未修改正式 Dijkstra 案例，也未向默认堆隐式增加 List 的字典序语义。
