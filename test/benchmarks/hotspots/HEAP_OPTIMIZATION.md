# 通用堆优化与 A/B

本文保留对应版本的实验快照；后续源码改进见 [惯用写法优化](IDIOMATIC.md)，当前结果以上一级最新 README 为准。

后续 `heap_callback` 已统一为三语言显式比较回调，历史跨语言比值不作为当前参考，见 [公平性修订](HEAP_CALLBACK.md)。

本轮只保留原生 heap 的通用 pop 调整策略，不改变 Dijkstra、Huffman 源码、图结构、记录类型或比较规则，也不新增算法专用 API。默认数值、原生比较函数及 Tapas 自定义比较函数共用同一策略。

## 实现与退化修复

原 pop 每层先比较两个子节点，再比较较小子节点与替换元素，以决定是否提前停止。堆顶由末尾元素替换后，替换元素通常接近叶子，这些逐层停止检查多半不能提前结束；若比较需要进入 VM，就会重复支付函数调用和记录索引成本。

首版改为先提升较小子节点至叶子，再把替换元素向上定位。普通回调堆的 B/A 约 0.65–0.69，但全相等回调堆达到 2.308：原版第一次检查即可停止，首版却无谓下沉再上升。这是比较次数随高度增长造成的结构性退化，不能当作随机噪声。[首版完整样本](experiments/heap_floyd_screen.json)。

最终版本先做一次根部检查：若替换元素已满足堆序就直接停止；否则先交换较小子节点，再沿下面的路径下沉、向上定位。首次严格比较已证明替换元素大于被提升的子节点，因此上升不必越过已经确定的堆顶。该判断只依赖严格弱序，不检查数值类型、记录字段或数据规模。

`heapify` 保留原先可提前停止的下沉；它的任意内部节点与 pop 的末尾替换元素具有不同的分布，不应为追求统一实现而一并强制下沉。

实现继续交换已有 List 槽位：比较函数调用前，所有复合对象始终由 List 持有。没有把一个拥有引用的元素暂存在未注册的 C 局部变量里跨越可能报错的回调；出错时不回滚排列的既有合同保持不变。未删除比较返回类型、List 结构变化或引用管理检查。

## 通用负载矩阵

[heap_ab_script.py](../heap_ab_script.py) 生成 15 组负载。两侧输入源码完全相同；每组每轮预热一次，再交替运行七对独立进程，三轮反转起始顺序。每次校验输出，记录所有原始 CPU 时间、配对比值、源码和二进制哈希。测量期间没有并行构建或测试。

基线是新增 fill/count 后、修改 heap 前从普通 Release 构建复制的二进制；候选沿用同一构建参数（-O3、IPO/LTO），没有 PGO。复制到临时目录的基线无法从旁边找到 CMakeCache，因此原始 JSON 的 build_config 为空；不代表用了另一套构建参数。

B/A 小于 1 表示优化后更快，IQR 是配对比值中间一半的范围，不是置信区间。

## 同源码综合算法与其他热路径

[全部 44 项运行时 A/B](experiments/heap_runtime_controls.md)及[原始样本](experiments/heap_runtime_controls.json)覆盖固定 16 项综合算法和 28 项热点。每项三轮、每轮七对，轮间打乱案例顺序。固定 16 项的配对比值几何平均为 0.987；这个约 1.3% 的总变化中，明确收益主要集中在 Dijkstra，其他接近 1 的变化不能统称为通用 VM 提速。

| 案例 | 基线中位数 | 优化后中位数 | 配对 B/A | 三轮 B/A |
|---|---:|---:|---:|---|
| Dijkstra | 8.100 ms | 6.942 ms | 0.860 | 0.844 / 0.857 / 0.871 |
| 优先级记录堆热点 | 11.253 ms | 8.766 ms | 0.779 | 0.779 / 0.782 / 0.777 |
| Huffman | 2.057 ms | 2.065 ms | 0.995 | 0.982 / 1.000 / 1.035 |

配对比值的中位数不等于两列独立中位数相除。Huffman 首批有一轮变慢，继续做三轮各十一对的[复测](experiments/heap_runtime_repeat.md)：B/A 1.009，三轮 1.018 / 1.009 / 0.997，IQR 0.989–1.030。独立计数确认它的堆比较两侧都是 38 次，绝大部分时间仍用于 40,000 字符的频数统计；现有数据不支持把约 1% 的变化判定为 pop 策略造成的稳定退化。List 复制也没有修改执行路径，首批 1.011、复测 1.013，复测 IQR 0.975–1.041；保留样本，不将其宣称为收益或确定回退。

独立插桩只统计工作，不采用插桩运行的耗时作为性能证据：

| Dijkstra 顺序 | 版本 | 比较次数 | 入堆 | 出堆 | 顶点展开 | 边扫描 |
|---|---|---:|---:|---:|---:|---:|
| 只比较距离 | 基线 | 100,624 | 7,420 | 7,436 | 4,000 | 28,000 |
| 只比较距离 | 优化后 | 75,676 | 7,412 | 7,428 | 4,000 | 28,000 |
| 距离、顶点字典序 | 基线 | 103,388 | 7,436 | 7,452 | 4,000 | 28,000 |
| 距离、顶点字典序 | 优化后 | 77,584 | 7,436 | 7,452 | 4,000 | 28,000 |

相同优先级的先后顺序本来就不保证，距离比较时入出堆数略变；统一为严格的字典序后，其他工作完全相同，比较仍减少约 25%。因此收益不能只解释为换了并列顺序、碰巧减少图搜索。[插桩源码及计数](experiments/heap_work_counts.json)。

## 公共回调入口：独立尝试，未纳入

另行尝试让所有原生调用 Tapas 函数的入口复用固定参数帧的快路径，保留参数复制、引用增加和慢路径回退；适用方包括 heap、finite 和 evaluators。与“只修改 heap”的候选独立比较，避免把减少比较次数的收益重复算作调用入口收益。[试验补丁](experiments/callback_entry_candidate.patch)。最终 src/runtime/tvm.c 已恢复原状。

源码检查发现原生入口已经复用帧池，并已对少参数复制作展开；这次尝试没有消除帧分配，也没有消除复合参数引用、执行比较体、结果移交与帧清理，只跳过一般入口的部分准备检查。

[首批入口 A/B](experiments/callback_entry_ab.json)中，普通回调/记录分别 0.968/0.967，捕获变量 0.990，循环较重的回调 1.024；再做三轮各十一对的[重复实验](experiments/callback_entry_repeat.json)，普通回调/记录均约 0.972，循环回调仍约 1.023。[finite::map 独立控制](experiments/callback_entry_finite.json)为 0.981；[综合与直接调用控制](experiments/callback_entry_controls.md)中 Dijkstra 0.984、Huffman 0.999，普通高阶回调 1.020。

不能据此断言循环帧保存逻辑变慢：普通高阶回调并不经过这个原生入口，而 bytecode 快路径的参数所有权模式仍是编译期常量。进一步检查[链接布局](experiments/callback_entry_code_layout.json)，新入口的文本跨度从 796 增至 2,024 字节，主分派函数跨度仍为 99,848 字节，但起始地址随之移动。内联增加代码和改变布局是已确认事实；是否具体造成指令缓存或预测变化，没有硬件计数器证据，不能说已精确定位那 2%。

本轮没有为几个样本选择对齐、填充或特判循环函数：当前尝试在已经复用的入口旁增加了一条较大的准备分支，只得到小幅且混合的端到端变化，不作为必需改动保留。这个决定结合了已存在的帧池、实际省掉的工作、代码增长和独立复测，不是看见小回退就恢复；也不代表公共回调开销已经解决或永远不值得优化。后续更有价值的方向是统一准备路径并减少真实参数/结果管理工作，而不是继续复制入口逻辑。

## 新热点、三语言参考与正确性

新增 heap_callback：复制优先级记录序列、二叉堆建堆、全部元素有序出堆并按位置加权。输入记录在计时前构造，复制、建堆和消耗均计时，不重复使用已排序结果。Tapas 的记录顺序需合法比较函数，Python 默认使用 heapq 与 tuple 内建比较；正式输入的优先级互不相同，因此只比较优先级与 tuple 字典序给出相同顺序。

Python 另测覆写 tuple.__lt__ 的子类，包装在计时前完成，显式进入语言回调；它会改变 Python 对象表示，只是诊断控制，不替换更快的默认参考。Lua 使用原地二叉堆与空槽移动，三轮源码 A/B 比原先逐层交换的版本耗时约低 15%，[完整源码与样本](experiments/heap_callback_lua_sources.json)。Lua 可以安全在局部变量中持有替换对象；Tapas 原生实现还需满足回调错误时的引用清理约束，不能机械照搬。

目录自动发现和 catalog/semantics 清单已更新，新热点、Python 结构对照都会进入同批生成的中英文 README。主表是当前普通 Release 对 Python 3.14 的跨语言结果；历史 PGO 构建不能与它直接作运行时 A/B。更新前的[中文主表](experiments/pre_generic_heap_README.md)、[英文主表](experiments/pre_generic_heap_README_en.md)、[原始测量](experiments/pre_generic_heap_comparison_results.json)已归档。

验证结果：

- Release：53/53；ASAN 下核心、数据结构、内建能力和语言回归：4/4。
- benchmark 报告脚本测试：12/12。
- 三语言 44 项固定校验和及 14 组综合算法小输入通过。
- 完整 DP 行、直方图与堆出队输出共 64 次检查；堆覆盖空输入、单元素、负数、重复优先级、有序、倒序和全相等。
- 语言回归补充全相等记录的比较次数上界、全部 payload 唯一保留及原生比较函数；现有测试继续覆盖嵌套回调、复合对象别名及错误路径。
- 20 份文档及两份主页、127 个可执行代码块、源码/字节码合同与输出快照通过检查。
