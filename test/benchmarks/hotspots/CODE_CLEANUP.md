# 代码结构整理与性能验证

本轮以逻辑清晰、职责明确和性能保留为标准。A 是整理前保存的普通 Release 可执行文件，B 是最终普通 Release 构建；所有 A/B 使用相同案例源码并校验结果。历史实验主表不据此替换为新的 Python/Lua 测量。

## 保留的改动

- 类型严格相等与赋值兼容分开：严格相等不把“能力信息未知”视为通配条件；赋值兼容允许未知能力，并递归处理容器和模板参数。二者共用图遍历和循环检测，避免复制一套结构比较。
- 扩展能力信息由 `textension_symbol_capabilities` 统一读取；是否存在声明与声明的能力位分开表达。未知状态仅在编译器边界转换成内部标记。
- 同时提供实例能力表和模板声明时，扩展注册要求两者一致；冲突声明在安装前被拒绝。
- 结构类型到内建容器的映射改成集中 switch，去除多层三元表达式。
- 新增严格相等、嵌套赋值兼容、模板参数约束、未知/空能力表和声明冲突回归测试。中英文 C 扩展文档同步。

## 未保留的成员检查优化

实验将字节和布尔成员检查改为 memchr。64 项输入耗时比约 0.68–0.74，65,536 项晚命中及未命中约 0.13–0.14；这些是候选实现结果，最终版本没有保留此改动。

最初将 libc 调用放进公共函数，ARM64 编译结果给实数路径也增加了栈帧。小型实数序列回退约 12%–19%。隔离并禁止内联字节查找助手后，该项回退消失。

不过，共享代码体积变化同时移动了后续排序和堆代码的地址。排序的五轮加长 A/B 仍有持续回退，而同二进制 A/A 未出现相同方向。因此没有把该现象简单解释为随机噪声。针对当前构建加入布局填充或扩大排序调优会增加维护成本，超出本轮结构整理的收益；最终撤回成员查找及其内联控制，保留原来的运行时实现。

| 排序控制 | 耗时比 B/A | 各轮中位数 |
| --- | ---: | --- |
| 成员优化候选，5 轮 A/B | 1.034 | 1.047, 1.034, 1.018, 1.048, 1.032 |
| 同二进制，3 轮 A/A | 0.981 | 0.975, 0.981, 0.997 |
| 最终版本，3 轮 A/B | 1.006 | 1.028, 0.985, 1.024 |

撤回后，排序和堆的关键函数地址恢复基线；Int 排序核心、紧凑计数及成员检查的反汇编与基线一致。其他位置仍可能存在字符串地址等链接重定位差异。

## 最终性能检查

固定 16 项综合算法，等权几何平均 B/A 为 **1.001**。每项 3 轮，每轮一次预热、7 次正式测量；进程交替运行，不并行执行测试或构建。该差异约 0.1%，处于本次测量波动范围，未观察到持续性能退化。

A SHA256：`bb1ba3e66bb6bb36cf8b4be0a2ffe345fc1d167322a928ad649251d4e3417a7a`

B SHA256：`e122256812628f8fb3001a34988ecc8947d1def236ecb201e514141611ee89c0`

| 控制项 | 最终耗时比 B/A |
| --- | ---: |
| list_sort | 1.006 |
| heap_order | 0.991 |
| heap_callback | 0.993 |

语言服务器另做 3 轮检查：每轮为每份文档启动新服务器，先预热 8 次编辑，再测量 32 次完整文本更新到诊断返回的墙钟时间。所有诊断均为空。该检查也覆盖模板/能力分析，而非只看排除了编译时间的算法计时。

## 数据与复现

- [最终 16 项算法及控制 A/B](experiments/readability_final_runtime_ab.md)；同名 JSON 保存原始样本、源码与二进制哈希。使用 `ab_script.py BASELINE CANDIDATE --runs 7 --rounds 3 --seed 17`，逐项选择固定 16 算法及 list_sort、heap_order、heap_callback。

- [候选排序/堆控制加长复测](experiments/readability_controls_repeat.md)与 [A/A 对照](experiments/readability_controls_aa.md)。

- `experiments/readability_lsp_ab.json` 保存语言服务器原始样本、两份输入源码、二进制哈希与完整测量脚本。
