# 热路径优化实施与 A/B 分析

后续新增的原生 heap 包及 Dijkstra、Huffman 写法优化单独记录在 [heap 实验](HEAP.md)。下文运行时源码 A/B 属于此前阶段，最新跨语言结果仍以上一级自动生成报告为准。

验收指标为固定 16 项综合算法的 Tapas/Python 3.14 耗时比几何平均 ≤ 0.90，各项等权。案例经过[跨语言语义与惯用写法审查](../SEMANTICS.md)修订；此前 0.894 的达标结论仅对应旧源码，现已归档，不能用于当前案例。当前数字以[中文报告](../README.md)与[English report](../README_en.md)为准。语言写法审查阶段的七次跨语言验收为 **1.266×**，未达到目标；该数字也已成为历史阶段结果。随后两项热点语义修订、最新测量与解释边界见[热路径逐项审查](AUDIT.md)。

普通 Release 的源码优化与完整 LTO + PGO 的构建优化分开做 A/B，不能把独立实验的百分比相乘作为目标验收。语言写法修订阶段的完整 43 项做过三轮、每轮五次有效样本的运行时 A/B；这组数据早于本次 dp_row / dict_counting 语义修订。该阶段源码 A/B 的综合算法 B/A 为 **0.916**（耗时下降约 **8.4%**）。完整 LTO + PGO 相对相同源码的普通 Release，综合算法 B/A 为 **0.958**（额外下降约 **4.2%**），热点为 **0.953**（下降约 **4.7%**）。最终数据见 [源码 A/B](AB_RESULTS.md)、[原始样本](ab_results.json)、[构建 A/B](PGO_AB_RESULTS.md) 和 [构建原始样本](pgo_ab_results.json)。

## 真正的性能缺口

原有单操作热点重复少数操作，无法代表综合算法中指令转换、容器键协议、对象构造、递归循环及组合索引的成本。新增诊断案例和同结构对照见 [诊断分析](ANALYSIS.md)。优化后的热点可以转为领先；热点的目的在于解释缺口，而非维持落后结果。

新增案例的 Python 默认实现使用 Counter、list.index、sum、元组及 slots 等适用的惯用写法，不用刻意缓慢的解释器循环充当唯一参照。跨语言比较和相同 Tapas 程序的运行时 A/B 分开进行。本轮修改的是各语言的惯用写法，不通过预存答案或换掉指定算法来改变任务；修订后同一份 Tapas 源码用于两端运行时 A/B，热点不计入目标平均值。

## 保留的通用优化

### 分派及指令组合

[src/runtime/tvm.c](../../../src/runtime/tvm.c) 保留各操作码独立的 computed-goto 出口，同一操作码内部的多个分支先汇合，限制分派复制带来的代码膨胀。空汇编只阻止编译器合并出口，不生成机器指令；switch 备用路径保留。

代码缓存预解码分派地址，运行时直接读取目标，避免重复提取操作码及二次查表。简单 PUSHX 在缓存建立时按静态字节码形状识别，临时值与当前局部变量走小型入口，复杂融合及上层环境读取仍使用原逻辑。新增入口共用一个独立出口，避免重新汇入复杂 PUSHX 的分派站点。没有增加序列化操作码或改变字节码格式。

Dictionary 数值字段的两次读取、加减乘除及写回可融合。形状学习和不匹配结果缓存在互斥的 union 中，不增加本机原有缓存条目的大小；较大的校验代码位于独立函数。动态检查接收者、字段、槽位和数值类型，立即写回以维持别名及操作次序。扩容、删除、类型变化、复合对象、重载、父环境以及整数除零使用原路径，不提前改变错误位置。

字符串索引产生的内部字节标记可直接用于相邻 EQ/NE 比较及条件跳转，省去中间字符串对象和分派。仅当比较双方都是内部字节标记且指令形状满足约束时使用；常量、变量、偏移、负索引及 UTF-8 的现有字节语义保持一致，List 和一般值比较回退。

成本：预解码每条指令增加一个指针，本机为 8 字节；初次建立缓存需要时间。解释器体积也增加。基准内部 CPU 时间排除启动、加载及编译，因此不代表冷启动性能。

### 哈希表的读取、比较和覆盖

[src/dsa/thashtbl.c](../../../src/dsa/thashtbl.c) 将只读探测从支持插入的探测中拆出：读取和删除不再维护首个 tombstone、插入探测计数或 found 输出参数。插入仍保留完整协议。键比较直接处理 nil、Bool、Int、Float 和 String，String 仍按内容比较，NaN 及正负零仍使用既有键协议；一般复合对象保留原有行为。

旧值与新值都是标量时，覆盖直接赋值，避免不需要的引用操作；复合对象仍遵守原来的持有、释放及别名规则。删除只清理需要释放的复合键和值，标量 tombstone 由槽位状态排除，重新插入时覆盖。此处赋值保留浮点值的正负零位模式。

[分配器声明](../../../src/dsa/tblockpool.h) 补充 malloc/alloc_size 合约，使编译器知道返回的是指定大小、不与其他存活分配重叠的内存；允许释放后复用。不把这项真实合约单独宣称为已确认的性能收益。

### 有界的短字符串共享

[src/runtime/objects/tstr.c](../../../src/runtime/objects/tstr.c) 将既有单字节共享扩展至全部两字节值，按需构造不可变对象并预存 hash。重复切片可复用对象及 hash，键相等时可命中指针比较。所有 65,536 种组合采用同一规则，支持零字节和高字节，不识别任何算法、字符集或键名。

单因素 [A/B](experiments/target90_pair_string.json) 的两轮 k_nucleotide 比值分别约 0.869、0.871；单字节 string_count 基本持平。不能将无相关分配路径的其他小幅变化也归功于该缓存。

在本机指针表占 512 KiB；对象按需产生，最多 65,536 个。sizeof(tstr)=72，全部填满时对象和表的请求大小合计约 5 MiB，另有分配器开销。对象与既有单字节缓存一样保留到进程退出。这是有上限的空间换时间，长时间嵌入式使用也应考虑该成本。

### PGO 与正确性修复

[PGO 构建说明](PGO.md) 提供完整命令及 [训练清单](pgo_training.json)。仅使用 27 项热点训练，固定 16 项综合算法不参与训练；最终可执行文件不带插桩计数器。普通 Release 默认配置未修改；完整 LTO 通过显式 Clang 参数启用，没有采用 CPU 专用或放宽浮点语义的参数。

完整 LTO 暴露 syntax 包将未初始化局部值传给先清理旧值的 setter 的问题，按项目惯例先初始化为 nil 后修复。未加入预解码的对照也失败，关闭严格别名优化仍失败，不能把问题归因于预解码。这项修复及 token 字段回归独立于性能优化。

## 退化分析与撤回依据

不以一次小幅差异决定取舍。[A/A](experiments/AA_RESULTS.md) 中多数轮次约有 1%–2% 波动，浮点个别轮次约 3.5%；这不是固定噪声上限。修订后 A/B 每项三轮、每轮五个有效样本，重新预热、交替顺序、打乱案例；报告保留配对比值、四分位区间及各轮中位数，四分位区间不是置信区间。

- 字段融合初版使无关浮点和调用热点明显变慢。采样与字节码确认其没有执行字段融合；汇编显示主解释器寄存器分配及布局发生变化。缩小入口、外提校验、缓存负结果，并汇合同一操作码出口后修复了明显退化，而没有直接放弃字段融合。历史证据见 [首阶段分析](experiments/DISPATCH_FIELDS_ANALYSIS.md)。
- 完整 LTO + PGO 的早期字典更新、删除回退跨轮出现。汇编显示 PGO 的删除调用了支持插入的探测函数，并经栈传递 found，而普通 Release 已内联探测。标量覆盖、只读探测与直接键比较分别测试，修复真实额外工作；不把全部变化归因于某一个加载或分支。
- 公平性修订前的完整 LTO + PGO 有构建取舍（[历史数据](experiments/pre_fairness_PGO_AB_RESULTS.md)）：相同源码下 dict_update 三轮慢约 10.7%–11.4%，dict_counting 慢约 5.2%–7.1%，k_nucleotide 慢约 3.3%–3.7%，不能当作随机波动。dict_update 在计时前已填表，覆盖已有整数键及标量值，不分配字符串；因此两字节缓存和新键分配不能解释这条回退。两种构建的 exec_tins 静态指令数分别为 24,962 与 17,740，调用站点分别为 542 与 325，完整 LTO + PGO 中还出现普通 Release 主函数未保留的 thashtbl_get 调用，说明内联与代码布局确实变化；[该阶段汇编记录](experiments/pre_fairness_codegen.json) 附二进制哈希。此证据限定了编译配置影响的方向，尚不能精确解释每个百分比或确认某个硬件事件。保留更快的普通 Release 选项，并以独立构建提供完整 LTO + PGO：它在预定综合目标上有整体收益，但不声称适用于所有字典密集工作负载。这一阶段普通 Release 的源码 A/B 没有案例的配对中位数回退超过 1%；当前数据单独列于最新报告。
- 将全部 PUSHX 按地址类型拆分后重新汇入复杂主体，回调和树负载变慢。静态筛选简单 PUSHX、使用小型入口，再给它独立出口，比无条件扩展入口更有效。中间步骤及未修复回退也保留原始数据。
- 整体外提算术融合增加调用边界；扩大通用比较融合没有消除实际的字节生产/消费成本；扩大调用帧复用没有绕开已存在的容量快速路径。这些实验未提供稳定整体收益，已恢复。
- 延迟空 List 分配减少空对象空间，却让随后成为非空的 List 额外分配头部和缓冲区。将首次增长由 16 调到 4 也没有解决综合收益不足，且增加规则，两个修改均恢复。没有为了减少分配指标而保留不改善目标负载的方案。
- 扩大默认 ThinLTO 范围、mcpu=native、省略帧指针均缺少独立稳定收益，未采用。标量退出时不清零也没有整体收益，还削弱状态不变量，已恢复。

各筛选版本及其覆盖范围见 [实验目录](experiments/README.md)。小样本筛选用于定位，最终 43 项正式 A/B 用于核对整体效果；尚未确认的小幅回退仍列在表中。

## 复现和验证

原基线为 `99ea72197b3e277c668a01124297b3ed7be1752e`，保存为 build-release/bin/tapas-ab-baseline，来源见 [基线记录](ab_baseline.json)。[最终源码补丁](experiments/final_runtime.patch) 基于同一提交。源码 A/B 两端使用同一编译器、Release -O3 -DNDEBUG 及默认 ThinLTO；构建 A/B 两端源码相同。JSON 保存二进制、源码及运行时 diff 的 SHA-256、构建参数、环境与全部样本。测量时没有并行构建或测试。

```sh
python3 test/benchmarks/ab_script.py \
  build-release/bin/tapas-ab-baseline build-release/bin/tapas \
  --rounds 3 --runs 5 --seed 20261017
# PGO 构建命令见 PGO.md
python3.14 test/benchmarks/compare_script.py \
  build-pgo/bin/tapas --runs 7 --require-algorithm-target
```

Release 和完整 LTO + PGO 均 **52/52** CTest 通过；AddressSanitizer 的 data_structures、core_no_stdlib、language_rules **3/3** 通过。回归覆盖值生命周期、别名、tombstone、NaN/正负零/嵌入零字节键、短字符串释放后再创建、缓存扩容/删除、类型与重载切换、捕获变量、源码/字节码入口及异常定位。运行器单测 **11/11** 通过；最终 switch 构建的 data_structures、core_no_stdlib **2/2** 及两个回归案例的源码/字节码 **4/4** 通过。

备用 switch 完整 language_rules 的既有 recursive_frames 卡住问题在未优化基线中也可复现，不将未完成检查算作通过。

## 尚存缺口

批量原生 Counter/list.index 能力、递归构树的对象表示和分配成本仍有差距。最终跨语言报告中的 string_count、while_search、recursive_loops、tree_build 等案例仍反映这些问题；几何平均达标不代表每项领先，也不代表所有平台达标。


## 公平修订后的结论

语言写法审查采用 Python 切片筛、Counter、map 点积、Dijkstra 的 heapq，以及 Lua 字节读取、table.move 和二叉堆等经过对照的实现。Tapas N 皇后提前退出、k-mer 默认值读取和 Huffman 原地删除同样纳入审查。详见 [合同与候选说明](../SEMANTICS.md)。

目标从修订前的 0.894 变为 1.266，说明此前用旧参考实现得出的达标结论不能证明面对惯用写法也达标。运行时收益应在相同源程序的 A/B 中判断；跨语言目标必须以最新版本实际测量，不能用历史收益推算。

当前构建 A/B 仍有 dict_update 的重复回退，约 8.9%–10.8%，保留在表中。它不应解释为噪声。完整 LTO + PGO 是可选构建配置，并未覆盖普通 Release；不能把其综合收益描述为所有热点均受益。最新 [汇编记录](experiments/final_codegen.json) 及其哈希对应当前二进制，不与修订前的汇编记录混用。

语义检查覆盖完整 **43×3** 个程序及 **14 组×3** 内核小输入，在普通 Release 与 PGO 下均通过；其中完整序列及不同输入用于补充固定校验和的局限。运行器 **11/11** 通过；重新训练后的 PGO **52/52** CTest 通过。当前两份 README 来源相同的一批七次测量，均明确标记目标未达到。

后续热路径审查已修复 dp_row 的非法前驱状态与 dict_counting 的伪计数，并重新训练 PGO、验证和测量；主 A/B 文件以页首注明的旧输入版本为准，不冒充修订后热路径的性能结果。
